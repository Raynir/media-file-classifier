# Changelog

Notable changes per release. Each release branch moves the Unreleased entries under its version (docs/development-workflow.md).

## Unreleased

### Changed

- The describer asks for at most 15 tags (the schema's `maxItems`, as its description already said) and sends a presence penalty of 1.5, which stops near-duplicate tags such as "cat calm", "cat still" (D350; OCR requests are unchanged).
- `evaluate` computes its exit code from the report it just built instead of reading the JSON file back; the query encoder's latency test runs in the non-parallel timing collection.

## M2 — 2026-11-15

### Added

- Relevance evaluation of the app's own search: the evaluation tool runs the app's describer and OCR over the corpus once (`analyze`, stored in `eval/analysis/`) and scores the real hybrid, vector and keyword search (`app-hybrid`, `app-vector`, `app-keyword`) against a pinned baseline run, with new file-name, tag-style and "should find nothing" queries, ranking flags and a `tune` sweep. The tuned defaults are RRF k 10 (was 60) and every keyword field weighted 1 (was title 4, tags 3, file name 2): hybrid recall@10 0.930 English, 0.741 Russian (+0.002, =), MRR 0.972 and 0.804 (+0.008, =), well above vector-only search. Results and parameters in `docs/search-index.md` (E09-S05).
- Sorting: a sort dropdown at the end of the results header (Relevance, Name, Date taken, File size, Date imported) with a button for ascending or descending. Names sort naturally ("IMG_2" before "IMG_10", ignoring case and folders), and every order has a stable tie-breaker, so paging never repeats or skips an item. The order is remembered separately for searching (Relevance by default) and for browsing (date taken, newest first, by default, instead of newest import) in `settings.json`. With a search, another order sorts only the results that pass the relevance cut. The sort keys are stored and indexed (library schema version 12; upgrading fills them when the library opens), so a page in any order reads an index instead of sorting every item. Select all now covers the right items in every order, searches included (E10-S04).
- Search as you type is faster at 100k items: the keyword index gains one-letter prefixes (library schema version 11; upgrading copies the index when the library opens, about 7 s at 100k items, once), the hybrid search takes its keyword candidates from the best matches without ranking and counting every match, and the typing pause is 200 ms instead of 300 ms. Search p95 over every prefix fell from about 3.9 s to 0.5 s, and from 5 s to 0.12 s for one or two letters; prefixes of four letters or more still reach about 0.5 s p95, mostly the match reasons of the first page. The benchmark simulates typing to compare pauses (MFC-988, MFC-989, MFC-990).
- Analysis controls: new items are analyzed automatically when "Analyze automatically" is on (default), collected for 2 seconds or 500 items and queued as one job. Analyze is in the item menu (with "Analyze only with…" for one analyzer), in the Library menu (pending items, current search results) and as a button for each indexed folder. Switching automatic analysis on offers to analyze the pending backlog, with the count. A run of 500 items or more asks first and shows about how long it takes, from the benchmark's image rate (a video counts as the frames it is sampled into, decoding time not included; no estimate before a benchmark has run). The progress time left for videos is still seeded with the image rate (E06-S06).
- Processing queue panel: View > Processing queue (or a click on the status bar's processing indicator) opens a window with the active, queued and recently finished jobs, each with progress, counts, time left and failures. A job can be cancelled (jobs with 100 or more unfinished items ask first; what it finished stays) and its failed items retried; Show failures lists each failed file with the stage that failed and the error, with Retry, and Reveal file in File Explorer. Finished jobs are kept only for the last 50 and 30 days: older ones are deleted with their work items when a library opens and when a job finishes (E05-S03).
- Filter panel: quick chips (All, Images, Videos) above the results and a Filters flyout with a control for every available filter, built from the filter's kind (check boxes, date presets and range, number range, tag include/exclude with suggestions, yes/no), so filters registered later appear with no UI change. The filters in force show as chips with a remove button and Clear all. The new setting "Restore the filters on startup" (off by default) brings back the filters you had set in a library when it opens; they are saved per library. Date and range filters can describe their presets and units through the optional `IFilterPresets` and `IFilterRangeInfo`.
- Core filters: date (today, last 7 or 30 days, this or last year, or a custom range, in the viewer's local calendar), resolution (small, HD, Full HD, 4K, or a minimum displayed width and height, so rotated portrait photos count as portrait), processing status (pending, indexed, error, missing), folder (indexed folders and subfolders, with or without their subfolders; Offline folders are marked and can still be picked) and tags (all or any of the included tags and none of the excluded ones, on the tags the item details show, so a rejected AI tag never matches; autocompletion from the library's tags). They join the media type and file format filters on every search path. The filter panel shows them once it lands (E10-S03).
- Analysis profile and endpoints under Settings › AI & Models. The profile section edits the open library's analyzers (search index, descriptions and tags, text in images): switch each on or off, choose its provider and model, and for descriptions the most tags and the language; changes save at once, and an analyzer with no provider, a missing provider or a provider that is down shows why. The endpoints section adds, edits, tests and removes OpenAI-compatible endpoints, finds a running LM Studio at `http://127.0.0.1:1234` and lists its models, and warns before images are sent to a host that isn't this computer (the endpoint stays unused until confirmed). Endpoints are kept in `settings.json`; API keys are kept in memory only (E17-S02).
- The production benchmark repeats the search-as-you-type scenario (a warm-up pass, `--typing-runs` runs per prefix, p50/p95 by prefix length) and times the real text encoder next to it, with the 300 ms pause added, so the numbers match what a user sees. Baseline at 100k items in `docs/search-index.md` (MFC-991).
- Testing rules in `docs/testing.md`, and shared test helpers in `tests/MediaFileClassifier.Testing` (`FakeSender`, `ForwardingSender`, `FakeHardwareInfo`, `InMemoryModelStore`, `SingleEntryModelCatalog`, `TemporaryFolder`) and `Ui.Tests` (`TestServices`, `TestLocalizer`, `FakeModelDialogs`) that replace the copies in about 40 test files. `dotnet test -- --hangdump --hangdump-timeout 3m` dumps the stacks of a hung run (MFC-992).
- Model and hardware settings under Settings › AI & Models. Models lists every tier of every catalogue model, installed or not, plus installed models the catalogue doesn't know, with size, precision, license and status: Download (with consent) or Import from file for a missing tier, Verify (hashes the files again) and Delete (asks first, naming the libraries that use the model) for an installed one. Hardware shows the detected execution provider and graphics card, lets you choose the provider (Automatic, CPU, DirectML, CUDA) and the model tier (Automatic, Standard, Compact), with the ones this computer or build can't use disabled and the reason shown, and runs the benchmark and shows its results. The choices are kept in `settings.json` and apply from the next analysis (E17-S08).
- Filter model: filters are registered definitions (media type and file format so far) that build their own SQL, so a new filter reaches text search, image search, Find similar and browsing with no change to the search service. Different filters combine with AND, the values of one filter with OR. The active filters serialise to and from JSON for saved searches and for restoring them at start; filters no longer registered are skipped. With filters set and no search text, browsing shows the matching items, newest import first (E10-S01).
- Search as you type: a search that was replaced while its answer was on the way no longer shows that answer, the first page of the last 32 text searches is cached so going back (for example deleting a character) is instant, the time from the last keystroke to the results is logged, and the production benchmark searches every prefix of a query. Short prefixes are still slow at 100k items (about 3.9 s p95), so the 300 ms target of D031 isn't met yet (E09-S02).
- Hardware acceleration and model tiers: SigLIP 2 now runs on the GPU when there is one. The ONNX Runtime DirectML build ships with the desktop app (+18.5 MB), on the adapter with the most dedicated memory (at least 2 GB, so a hybrid laptop uses its discrete GPU). A provider that is missing, fails to load or fails its first run falls back to the CPU, with the reason logged. Model tiers install side by side in `models\<id>\<version>\<tier>\` (older installs are moved on first use), the usage list is kept per tier, and the tier that suits the hardware is used: fp32 `standard` on the CPU, fp16 `compact` on a GPU. `--benchmark` times SigLIP 2 per tier and provider on generated images, saves `benchmark.json` and gives the estimated time remaining a rate to start from before the first items finish. `docs/hardware-matrix.md` lists the machines checked and the gaps (E06-S08).
- Find similar: Find similar on an item (context menu, details panel, `Ctrl+Shift+F`) lists the items that look like it, most similar first, within the current browse scope, with the item itself pinned first and marked Source. The search box shows a "Similar to: <name>" chip with its thumbnail; typing text replaces it, and its clear button or Escape goes back to browsing. For an item that hasn't been analyzed yet, the chip offers Analyze now, which analyzes it ahead of other work and shows the similar items as soon as its embedding is ready, or says why it couldn't (analysis failed, processing paused or not running) (E09-S03).
- Image-to-image search: pick an image with the search bar's image button, drop one on the search bar, or paste one into it, and the library is ranked by visual similarity to it. The picture is embedded on the fly with SigLIP 2 and never added to the library; JPEG, PNG, WebP and GIF are accepted (an animation by its first frame), checked by content like an import, up to 64 MiB. The search bar shows the picture as a chip with its name, typing or Clear replaces it, the browse scope still applies, and the notice says when the image model is missing or the index is still loading (E09-S04).
- Analysis pipeline: an Analyze command queues one AI-pool work item per item that runs the library's analysis profile (SigLIP 2 embedding, image describer, OCR, in that order by default) on one decode of the picture or one sampling of the keyframes, and stores each analyzer's result with its model and prompt version, plus a per-analyzer state (done, failed, skipped with a reason, retrying). One analyzer failing doesn't stop the others: an item whose embedding is done is Indexed even if its OCR failed, with a retryable OCR failure, and only an embedding failure puts the item in Error. A describer or OCR provider that's down is skipped and its work waits for it; pictures are sent to OpenAI-compatible endpoints as JPEG (library schema version 10, E06-S01).
- Unified text search: the search box in the toolbar searches by keywords and by meaning at once (SigLIP 2 vectors merged with the keyword results), 300 ms after the last keystroke, for words in titles, descriptions, tags, text in images, transcripts and file names, in any language or script, and symbols or emoji alone never break it. Results that only the meaning search found and that fall below a per-model relevance threshold are hidden, with a "Show N less relevant results" option above the results; hovering a result says why it matched (the fields, or a visual match). The notice also says when the image model is missing or the search index is still loading and only text matches are shown (E09-S01).
- Semantic embeddings with SigLIP 2 base-patch16-256 (ONNX Runtime, local): image and text embedding in one 768-dimension space for English and Russian, a Pillow-exact image preprocessor, the Gemma SentencePiece tokenizer, an item analyzer that stores one vector per still and one per keyframe plus their mean for videos and animations, and a query encoder for text and image queries that keeps the text model loaded while a library is open and caches 256 queries. The evaluation runner can score the app's own pipeline: `evaluate --system siglip2 --models <folder>` (E06-S03).
- Search model download: a model catalogue that ships with the app (SigLIP 2 base, standard and compact tiers, pinned to the publisher's revision with SHA-256 hashes), a download with the size, license and source shown for consent, progress and Cancel, that checks each file's size and hash and leaves nothing behind when it fails or is cancelled, and a banner in the main window while the search model is missing, with Download, Import from file, and Retry after a network, disk-full or damaged-file error. Analysis jobs that need a missing model wait in "Waiting for model" instead of failing, and start once it is installed (E06-S12).
- Frame sampling for videos and animated images: 4 to 16 keyframes, one per 5 seconds, at even positions (by display time for GIF and WebP), with blank frames and near duplicates dropped by perceptual hash; keyframes store their perceptual hash, and per-frame tags, OCR text and embeddings combine into item-level results (library schema version 7, E06-S02).
- Search index engine: keyword search over the effective title, description, tags, OCR text, transcript, other descriptive fields and file path (FTS5, case and diacritics ignored, every word as a prefix, path substrings through a trigram index), in-memory vector search over half-precision embeddings of one model at a time, hybrid ranking with Reciprocal Rank Fusion, filters for media type, format, date, resolution, favorite, status, review status, collection, user tags and folder on every path, and an index rebuild. Metadata edits are searchable as soon as they are saved; libraries move to schema version 6 and rebuild their keyword index once when opened (E01-S04).
- AI provider abstraction: capability interfaces (image description, OCR, transcription, image and text embedding) that any provider implements in part, base classes for ONNX, OpenAI-compatible (LM Studio, Ollama) and native-library providers, a provider registry with capability lookup and health checks (missing model, unreachable endpoint, native library that won't load), a JSON schema for LLM image descriptions with repair and one retry, a per-user model store with SHA-256-verified import and deletion that names the libraries using a model, a query for items left outdated by a model change, and deterministic fake providers for tests (E01-S05).
- Toolbar above the media browser and details panel while a library is open: slots for the search bar, filters, sort and view controls in a fixed order, with the thumbnail size slider now in the view slot; an Add folder… button (also Library › Add folder…, `Ctrl+Shift+O`) that picks a folder and opens the Indexed folders dialog with it added; and a More menu (⋯) that takes the actions that don't fit as the window narrows (E13-S03).
- Manual rescan: Rescan library (Library menu and toolbar) and a Rescan button for the selected folder in the Indexed folders dialog compare the files on disk with the library. New files are imported; moved and renamed files keep their items, tags and favorites (matched on fingerprint and size, confirmed by the content hash); changed files get new metadata and thumbnails and are analyzed again while the user's edits stay; files that are gone are marked Missing; a damaged file that is replaced with a valid one is processed. A message sums up the result. Library › Remove missing items… deletes the Missing items after a confirmation, and the media filter can select them (library schema version 8, E02-S04).
- Error handling and retry for background jobs: failures are classified as transient, permanent or configuration problems; transient ones (an unreachable or busy AI endpoint, a locked file, a timeout) are retried up to 4 times with exponential backoff and jitter (2 s to 1 min) before an item is marked failed. An AI provider that fails 3 times in a row (or isn't configured) is paused: work that needs it waits instead of failing, its health is checked every 15 seconds, and the work resumes when it's back. The status bar shows "LM Studio unavailable" with the reason while a provider is paused (click to check now), and the processing tooltip counts work that is retrying. Library › Retry failed items and Retry if failed in the item and context menus retry failed items by hand (library schema version 9, E05-S04).

### Fixed

- AI image descriptions and OCR can no longer loop until the model's context is full: the requests set an output limit (4,096 tokens for a description, 2,048 for OCR) and send the description schema's length and item limits as JSON schema keywords that LM Studio enforces. OCR text that was cut off at the limit while repeating itself keeps one copy of the repeated lines (E09-S05).
- "Analyze search results" with no search active reads the browse list in one go, so deleting items meanwhile (remove missing, removing a folder) can no longer skip some. "Analyze pending items" leaves out items that an analysis run finished while the list was read, so they are neither counted nor analyzed again (MFC-995).
- "Analyze pending items", folder analysis and "Analyze search results" no longer skip items when the scope changes while it is read (for example pending items being analyzed by a running job): the scope's item ids are read in one query (or from the search's own list of hits) before the items are loaded, so the run covers every item the scope had when it started (MFC-994).
- The browse Subfolder scope (the folder tree and the results grid) ignores case in every alphabet, like the folder filter: `Фото` and `фото` are one folder. The date and resolution filters list their presets through `IFilterPresets` only (MFC-993).
- Two timing tests that failed only in a full `dotnet test` (`WriteConcurrencyTests` and `JobSchedulerTests`) now run alone, in a non-parallel collection (MFC-992).
- A finished job no longer stays in the progress summary and the status bar when its last work items finish at the same time (MFC-985).
- The SigLIP 2 quality test (`Siglip2QualityTests`) is opt-in: it skips unless `MFC_QUALITY_TESTS=1`, so it no longer uses every CPU core in a full `dotnet test` and starves the timing tests. Opt-in tests are documented in `docs/development-workflow.md` (MFC-986).

## M1 — 2026-11-04

### Added

- Settings window (Tools → Settings…, Ctrl+,): settings registered by features, with generated controls per category, search by name, reset per category or for all, and app or library scope shown on each setting; the theme choice is now saved, and `settings.json` moves to schema version 2 (E17-S01).
- A status bar under the main window, with segments that features add without changing it, and a View › Status bar toggle saved with the layout (E13-S04).
- Welcome screen and create-library dialog: a first launch offers to create a library in `%USERPROFILE%\Media File Classifier` or another checked location, opens it, and asks for the folders to index; Library → New library… does the same later (E02-S01).
- Opening libraries: Library → Open library…, a recent-libraries list on the welcome screen that marks unreachable libraries and lets you remove them, the last library reopening on startup (General → Open the last library on startup), clear messages for libraries in use, missing or from a newer app, and a progress window while an older library is updated, with an offer to restore its backup if the update fails (E02-S02).
- Keyboard shortcuts from one keymap, bound to physical keys so they work the same on English and Russian layouts, with focus scopes, text fields that keep their typing and editing keys, and a shortcut reference (`F1` or `?`, Help › Keyboard shortcuts) (E16-S01).
- Supported format registry: JPEG, PNG, WebP, GIF and MP4 are detected from their content rather than their extension; GIF and WebP files are told apart as still or animated, MP4 files need a video track, and other files are skipped with a reason (E03-S01).
- Technical metadata extraction: image EXIF, IPTC, XMP and ICC data (dimensions, orientation, date taken, camera, lens, GPS, color space) through MetadataExtractor; frame count, duration and loop count of animated GIF and WebP files; video duration, resolution, frame rate, codecs, audio track, creation time and rotation through FFprobe, with file-level metadata only when FFmpeg is missing. The date taken falls back from EXIF to the video creation time to the file modification time and records its source; damaged metadata gives partial results and warnings (library schema version 3, E03-S03).
- Job system: persisted jobs and work items (library schema version 4), a scheduler with I/O, CPU and AI pools and priorities, "visible first" boosting, cancellation, restart recovery, a clean stop when the library closes, and a confirmation when quitting while work is pending (E05-S01).
- Thumbnails in two sizes (256 and 512 pixels, WebP) for images, animated images and videos: EXIF and video rotation applied, blank first frames and black video intros skipped, videos read through FFmpeg with a placeholder and a warning when it is missing. Thumbnails are stored per item in the library's sharded cache, and a thumbnail cell shows a media type placeholder while a thumbnail is pending or after it failed (E03-S04).
- Media browser: an open library shows its items newest first in a virtualised thumbnail grid that stays smooth at 100k items, loads results in pages and thumbnails in the background (on-screen items get theirs first), shows Pending and Error badges, video durations and an animated marker, and opens an item in its default app on double-click or Enter. The thumbnail size (96–384 px) changes with the slider, Ctrl+mouse wheel or `=` / `-`, and is remembered per library (E14-S01).
- Import pipeline: adding folders imports them in the background. Files are found, fingerprinted, read for metadata and thumbnailed in parallel, appear as Pending analysis as they're registered, and are hashed in full afterwards at low priority so exact duplicates are grouped; a failed file is marked Error with its stage and can be retried, damaged files only once they change; imports resume after a restart, can be cancelled, and never create duplicate items (library schema version 5, E03-S07).
- Navigation panel: Library (All media, Recently imported) and Folders sections with live counts; the folders tree shows subfolders from the indexed items, marks Offline folders, and scopes the media browser to the selected folder or subfolder; Excluded items are no longer shown; sections collapse and stay collapsed; the collapsed panel is an icon rail; folders dropped on the panel are added through the folders dialog (E13-S02).
- Indexed folders: Library → Manage folders… lists the folders with their state and item counts; adding a folder imports it, a folder inside an indexed one is refused and indexed folders inside a new one are merged into it with their items and metadata; excluded subfolders and the hidden-file and cloud-file toggles mark excluded items Excluded and bring them back when the exclusion is removed; removing a folder removes its items from the library only, after a confirmation; unreachable folders show as Offline with their items kept (E02-S03).
- Media identity: quick fingerprints and full content hashes (XxHash128), perceptual hashes for images, a near-match search, and a file matching service with four tiers and confidence levels; a robustness test set of re-encoded, resized and converted copies (E01-S06).
- Progress reporting: counts per job and stage taken from the job system's work items, totals marked "so far" while a job is still finding work, an estimated time left from the last 30 seconds of throughput, and a status bar indicator ("Fingerprinting: 120 of 340 · 12 min left") updated at most twice a second (E05-S02).
- Selection in the media browser, as in Windows Explorer: click, Ctrl+click and Shift+click; arrows, Page Up/Down, Home and End move the focus and select, with Shift extending and Ctrl moving only the focus (Ctrl+Space toggles); Select all (`Ctrl+A`, Edit menu) selects every result without loading them and leaves out items added later; Esc or a click between tiles deselects. The selection keeps items still in the results after a refresh, and the status bar shows how many are selected (E14-S03).
- Context menu in the media browser: right-click or the Menu key on the selection offers Open in default app (`Ctrl+O`), Reveal in File Explorer (`Ctrl+Shift+R`) and Copy file path (`Ctrl+Shift+C`, every selected path, one per line); right-clicking an unselected tile selects it, entries that don't apply are hidden, and Open and Reveal are disabled with the reason for missing files and offline folders (E14-S04).
- Preview and details panel: the selected item's preview, title, quick actions (Open, Reveal) and Overview (description, tags) and Technical (type, format, dimensions, size, status, date taken, camera, video details, location, folder, path) tabs; the preview loads a screen-sized version of the original first and full resolution when zoomed (mouse wheel, Fit, 1:1, drag to pan) with EXIF orientation applied, and shows the thumbnail for missing files and offline folders; it can be resized and collapsed, and its tab and size are remembered. Enter or double-click in the grid shows the panel, ←/→ there move through the results, Enter opens the default app and Esc goes back to the grid (E14-S05).
