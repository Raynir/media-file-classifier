# Changelog

Notable changes per release. Each release branch moves the Unreleased entries under its version (docs/development-workflow.md).

## Unreleased

### Added

- Activity log (MFC-215): View > Activity log opens a window that lists what the app did to the library, newest first and grouped by day: imports, rescans, analysis, bulk edits and added or removed folders. Filter chips (All, Imports, Rescans, Analysis, Edits, Folders, Duplicates, Exports, Errors), a "Show items" link that selects the folder, paging, and a live refresh. The newest 5,000 events are kept. The library schema is now 17. Details: `docs/activity-log.md`.
- Folder watching (MFC-135): while a library is open, each Online folder is watched for new, changed, deleted and renamed media files. A file is reported once it has been quiet for 2 s and stable for another 2 s and opens for reading, so a long copy is reported once, after it completes; a locked file is checked again with the wait doubling up to 30 s. Temporary files, Office lock files, partial downloads and editor swap files are ignored by default; the list is the new General setting "Files to ignore while watching folders" (`monitoring.ignorePatterns`); a pattern without `/` matches file names only, and `**/name` ignores a folder. The folder's rules, the supported formats, partial folders and excluded items apply as in a rescan. When the watcher loses events (its buffer overflows or it fails), the folder is rescanned; if the folder's import or rescan work is running, the rescan is asked for again every 15 s. A watcher that keeps failing on a reachable folder is restarted after 1 min, then 2, 4 and so on up to 30 min, instead of at once. Changes are detected only; processing them comes with MFC-136 (no schema change).
- Change processing (MFC-136): the changes a watched folder reports now reach the library as an import job of the folder ("Import changes in …", import priority), so pausing processing holds them too. A new file is imported; a changed file is checked and re-analysed only if its content changed, keeping tags, notes and ratings; a renamed or moved file, or a whole renamed folder, keeps its item, ID and metadata with no re-analysis (5,000 items relink in about 2 s), including files that swap names; an excluded file that's moved stays excluded. A deleted file waits 30 s before its item is marked Missing, and only if the file is still gone and the folder can be reached; a file that appears meanwhile with the same content (a move done as delete and create, within the library) relinks the old item. A burst of changes, such as a copy of 2,000 files, makes one job: changes are gathered until none come for 3 s (30 s at most) and join the folder's job while it runs. Moves between drives (copy, then delete) aren't paired yet: the copy is a new item and the old one goes Missing (MFC-1052). No schema change.
- Startup synchronisation (MFC-137): when a library opens, a quick sync runs in the background as one low-priority job (import priority) over its Online folders, so files added, changed, moved or removed while the app was closed are picked up without waiting. It starts after the folder watchers run, shows in the processing queue, waits while processing is paused, and shows a notification and an activity-log entry only when it found a change. The new library setting "Check for changes when the library opens" (`monitoring.quickSyncOnOpen`, on by default) turns it off for very large or slow drives. An unchanged library of 50,000 files syncs in about 0.7 s on an SSD (no schema change).
- Drive connect and disconnect (MFC-138): ejecting a drive from the tray is no longer refused as "in use" by the folder watchers or by a video or animation shown in the details panel; they let go of the drive (the preview shows the thumbnail) and pick it up again if the eject is cancelled. A drive that goes away makes its folders Offline without marking any item Missing, also when the watcher or a rescan notices it first. When it comes back, its folders are Online again and caught up with a quick sync, whatever the "Check for changes when the library opens" setting says. Each folder now remembers its drive's volume serial number: plugged back in under another letter, the folder follows it (its paths change, items are kept, and the activity log says "Folder moved to a new drive letter"), while another drive that takes the folder's letter is never scanned as the folder. The library schema is now 18. Details: `docs/indexed-folders.md`.
- Pause and resume (MFC-194): background processing can be paused as a whole, per kind of work (disk, processor, AI analysis) and per job, from the processing queue and from a pause button next to the processing indicator in the status bar. Work already running gets 2 seconds to finish, then goes back in the queue, so nothing is lost. A new setting, "Keep processing paused after a restart" (on by default), keeps the pause when the library opens again; the global and per-kind pause is stored in the library settings (no schema change).
- Monitoring controls and status (MFC-140): Settings > Library has a "Monitor folders for changes" switch (stored in the library; off stops every watcher, on again runs a quick sync) and a threshold for notifications. The indexed folders list shows each Online folder's state next to its count: Watching, Paused, Can't watch or Not monitored. "Pause monitoring" in that dialog holds all folder monitoring for this session, and a "Monitoring paused" notice in the status bar resumes it; changes found meanwhile are imported on resume. A monitored burst is one "folder monitoring" event in the activity log and, when it has at least 10 changes (setting), one notification such as "12 new items imported from Camera Uploads". Per-folder Watch / Poll / Manual modes follow with MFC-139.

### Fixed

- Drive letters (MFC-1046): a folder could forget its drive's serial number when an availability check and a rescan or import wrote the folder at about the same time, so it no longer followed its drive to a new letter and another drive under its letter was taken for it.
- Drive names (MFC-1055): an Offline folder could lose its drive's name or serial number when a rescan, an import, a rule change or "Index whole folder" stored the folder at about the same time as an availability check.
- Drive letters (MFC-1045): a folder now remembers its drive's serial number as soon as it's added, not only after the next availability check, so a drive unplugged or swapped right after adding a folder is recognised.
- Drive letters (MFC-1044): a folder that followed its drive to a new letter could be stored Offline by a second availability check running at the same time, which stopped its watching and its catch-up.
- Folder watching (MFC-1047): changes seen while a watched folder's drive was briefly unreachable were dropped until the next rescan when the folder turned out to be still Online; the folder is now rescanned right away.

## 1.0.1 — 2026-11-22

### Fixed

- Analysis on the GPU (MFC-1038): with AI analysis set to run more than one item at a time, the app could close with a Windows error (0xC0000005) while reading text with in-process OCR on DirectML, because two items ran the same model at once and DirectML allows only one run at a time. Runs of a model on the GPU now wait for each other; other work still runs in parallel. If the GPU device is lost during analysis (driver reset or hang), the model moves to the CPU and analysis goes on, slower, instead of failing every later item until restart. The log now names each item and analyzer before it starts, so a native crash shows the last item. `docs/development.md` explains how to turn on Windows crash dumps.
- Processing queue (MFC-1039): a job's stage is named in words ("Analyzing", "Checking changed files") instead of by its internal key ("analysis.item: 208 of 237"). The analysis, rescan and folder-removal stages were missing their names. A stage that still has no name shows its job's description, in the progress text and in the failure list, and logs a warning once; a test fails when a stage has no name.

## 1.0.0 — 2026-11-22

### Added

- Command line (MFC-1024): `--data-dir <folder>` keeps the app's data in that folder in any build, so a published Release build can be tried on a throwaway folder. End-to-end pass report: `docs/release-checks/1.0.0-e2e.md`.

### Changed

- Offline folders (MFC-1014): when several folders change status at once, for example when a hub with many indexed folders is unplugged, the results and the details panel now refresh once, about a quarter of a second after the last change, instead of once per folder (no schema change).

### Fixed

- Background work (MFC-1025): when the view scrolls while work is starting, the items now on screen are processed next; before, one item from the previous screen could run first.
- Tests (MFC-1025): a plain `dotnet test` no longer fails at random on a busy machine. Bounds on how fast the code runs are checked only with `MFC_PERF_TESTS=1` (docs/testing.md), and the import cancel test no longer assumes that the scan has ended when the import is cancelled.
- Filter chips (MFC-1028): the selected chip ("All") is readable in the light theme; its text was white on light grey. The checked chip now takes its text colour from the theme's primary text token.
- Browser (MFC-1027): the empty band of about 90 px between the toolbar and the filter chips is gone; the header that holds the buttons for reopening a collapsed panel now takes space only when one of them shows.
- Details panel (MFC-1029): a field's header row (label, AI badges, Confirm AI, Revert, Undo) wraps onto a second line in a narrow panel instead of cutting off "Confirm AI".
- Release build (MFC-1030): the published app no longer ships .pdb symbol files or the ONNX Runtime import library (`onnxruntime.lib`); about 110 MB less. Builds still produce them. A crash log's stack traces keep method names but lose file and line numbers.
- Main menu (MFC-1021): Open item, Previous and Next, Select all and Select none, Library information and Refresh results are now disabled, with a tooltip that says why, when there is no library, no results or no selection to act on.
- Dialogs (MFC-1012): a dialog now opens with the keyboard focus on a control instead of on the window: its first text box, list or combo box, else its default button (Cancel in Remove item, the typed-name box in Delete library). Before, the first Tab only reached the first control. The UI smoke tool has a `dialog-focus` step.
- Keyboard (MFC-1011): Enter and Space on a focused button, such as the Filters chip, press the button instead of running a shortcut. Enter on the Filters chip used to open the selected item, so the filter flyout never opened from the keyboard.
- Main menu (MFC-1016): commands that don't apply are now disabled, with a tooltip that says why, instead of staying enabled. For example Edit, "Undo bulk edit" is off until there is a bulk edit to undo, and Select none is off without a selection. The menu rechecks every command when it opens (MFC-1017).
- Importing a model from files (MFC-1016): "Import from file" now asks for the folder that holds the model files and picks the ones the catalogue expects by name, so a model's files no longer have to be picked one by one (MFC-1018).
- List view (MFC-1016): the Favorite column's header shows a star icon, with the name in its tooltip, instead of looking like an empty column (MFC-1020).
- Processing queue (MFC-1010): a job that's given more work which then fails to be stored now still reports finished, with its completion notification, and leaves the processing queue and the status bar. When a large batch fails part way, the work items already stored are still counted, so a job's progress no longer goes wrong or below zero (no schema change).

### Added

- Documentation and licences (MFC-1026): the README is now for users: what the app does, system requirements, downloading and running a release, getting the models (download or import from a folder), the optional model server and `ffprobe`, where data, settings and logs are, privacy, known limitations and how to report a problem. The developer guide moved to `docs/development.md`. `LICENSE` is the Apache License 2.0 (D504). `THIRD_PARTY_NOTICES.md` now matches the packages the Windows app ships (LibVLC, DirectML, Avalonia.Labs.AnimatedImage and Microsoft.Extensions.AI added, ONNX Runtime corrected to 1.24.4) and the four models in the catalogue, which are downloaded, not shipped. The release zip holds `LICENSE`, `THIRD_PARTY_NOTICES.md` and a `licenses` folder with the LGPL-2.1 and DirectML texts.
- About and releases (MFC-1023): Help, "About Media File Classifier" shows the version and commit of the build, for example `1.0.0 (3bace9e)`, and the repository address; the first line of the log carries the same text. `tools/publish-release/New-Release.ps1` builds the self-contained Windows zip and creates the GitHub Release with the notes from this file. The release steps in `docs/development-workflow.md` are rewritten for `v<version>` tags.
- UI smoke tool (MFC-1013): `popup-key` and `popup-shot` steps and `wait-for popup` / `no-popup` send a key to, and capture, the open flyout, context menu or combo drop-down, so keyboard use of popups can be checked by script.
- AI & Models settings (MFC-1016): an "Open models folder" button shows the folder where models are stored in File Explorer (MFC-1019).
- Library menu, "Compact database" (MFC-1022): a deleted folder or pruned jobs leave free space inside the library's database file, which SQLite never gives back on its own. The command says how much a compaction would return and asks first, then rewrites the file in the background with `VACUUM`, with a status bar entry. It doesn't start while the processing queue has work, needs free disk space of about twice the data, and says when there is less than 4 MB (or 10% of the file) to gain. In a test, a 446 MB library with 80% deleted shrank to 89 MB in 0.7 s (no schema change).

## M5 — 2026-11-21

### Added

- Offline and missing items (E14-S07, MFC-127): items whose folder is offline show dimmed with an Offline badge, and missing files with a Missing badge, in the grid and the list; the badge tooltip names the drive to connect by its volume label ("Offline: drive 'Backup-2TB' (E:\Photos)"), else its letter or network share, and the details panel says the same. A Missing item's context menu offers "Remove missing items…". The filter panel has a "Hide offline items" check box, saved with the filters and saved searches. Folder statuses now follow drives live: plugging a drive in or out rechecks the folders within about a second, and offline folders (such as network shares) are rechecked every 30 seconds, so a reconnected drive's items go back to normal on their own. An offline or missing video's keyframe strip now says why its moments can't be opened in a player, and choosing one still shows its time (MFC-1007). Library schema 16 stores each folder's volume label.
- Keyboard navigation (E16-S03, MFC-131): F6 and Shift+F6 move the focus through the main areas: navigation, toolbar, media browser, details and status bar (a hidden area, or one with nothing to focus, is skipped), and back to the control that had the focus there last. While a narrow-width drawer is open, the focus moves into it, Tab stays inside it, and Esc gives the focus back to where it was. Every control now shows the same keyboard focus ring, drawn from the focus colour token (`Brush.State.Focus`, `Border.FocusRing`) in both themes, for keyboard focus only. The UI smoke tool has a `dialog-key` step, and `tools/ui-smoke/keyboard-*.smoke` check the keyboard paths.
- Default shortcuts (E16-S02, MFC-130): the whole default keymap is now bound. New: Ctrl+F or / focuses the search box (/ only outside text fields), F5 runs the current search or browse again (Edit and View menus, command palette), Ctrl+F5 rescans the library, and F toggles favorite while the grid or the viewer has focus (Ctrl+D still does too). Every row of the keymap table is covered by a test, and none of the defaults uses a Windows system shortcut (no schema change).
- Delete a library (E02-S07, MFC-122): Library, "Delete library…" (also in the command palette) deletes the open library, and a delete button on each reachable library in the welcome screen's recent list deletes a closed one. The confirmation shows the item count, says that media files aren't touched, and enables Delete only once the library's name is typed exactly. Deleting is permanent: it closes the library first, deletes only the files the app writes into the library folder (database, lock file, thumbnails, migration backups), removes the folder if nothing else is left in it, and drops the library from the recent list. Anything else in the folder stays, and the app says so. A library open in another window can't be deleted, and a delete that was cut short can be finished by deleting again (docs/library-storage.md; no schema change).
- Responsive layout (E13-S07, MFC-128): the main window now has three layouts by width. Wide (1100 and up) docks both side panels as before. Medium (800 to 1099) turns the navigation into an icon rail, whose expand button opens the full panel over it, and makes the details panel a drawer. Narrow (under 800) makes both panels drawers. A drawer slides over the browser above a dimmed backdrop; click the backdrop, press Escape or pick a navigation entry to close it, and the buttons at the ends of the results header open it. Your saved panel layout isn't changed by narrower windows and comes back when the window is wide again. Every command stays reachable at the minimum size, 720 x 480 (docs/responsive-layout.md; no schema change).

- List view (E14-S02, MFC-126): two buttons at the end of the results header, and View, "Grid view" and "List view" (also in the command palette), show the results as a list instead of the thumbnail grid: one row per item with a small thumbnail, Name, Type, Date taken, Size, Resolution, Duration, Status, Folder (hidden at first) and a favourite star. The list scrolls like the grid, so 100,000 items stay smooth. Click a column header to sort by it (Name, Date taken, Size; a second click reverses the order, and the arrow follows the sort control); drag a header edge to resize, drag a header to move it, right-click a header to show or hide columns or reset them. The column setup and the last view are remembered across restarts; switching views keeps the selection and the first item on screen (no schema change).

- Drag-and-drop import (E03-S06, MFC-125): drop files and folders from Windows File Explorer on the main window. While you drag, the window dims and a card says "Drop to import" (nothing shows without an open library, and over the search bar a drop is still a search by image). Dropped files are imported like picked files (E03-S05); dropped folders open the indexed folders dialog with the usual overlap and merge questions; one toast then sums up the files being imported, already in the library, left out, not supported or unreadable, and the folders added. Dropping folders on the navigation panel now goes through the same handler, so files dropped there are imported too.

- Library settings (E17-S04, MFC-133): Settings, Library shows the library's location with Reveal and Copy path above its counts and disk usage, hosts the indexed folders (add, remove, rules, rescan) and the excluded items (restore, forget), and has Refresh search index, Regenerate thumbnails… and Check library integrity as buttons, so every library operation is reachable from settings. The sections follow the open library and say "Open a library to see this." without one.
- General and appearance settings (E17-S05, MFC-134): Settings, Appearance has a new "Show file names under tiles" switch (on by default) that hides the file name line under each thumbnail at once and keeps the type and size line; Settings, General has a "Show informational notifications" switch (on by default) that the in-app notifications (E15-S01) will follow. The theme, "Open the last library on startup" and "Restore the filters on startup" settings were already there.
- Library maintenance (E02-S06, MFC-121): the Library menu and the command palette have Refresh search index, Regenerate thumbnails… and Check library integrity. The index refresh and the integrity check run in the background with a status-bar segment (click to stop). Regenerate thumbnails asks for "Only missing or outdated" or "All" and queues a thumbnail job in the processing queue, items on screen first; "All" deletes the item thumbnails first and keeps the keyframe pictures; neither runs while an import or rescan is unfinished. The integrity check shows a plain-language report; when the database is damaged and a migration backup exists, Restore backup puts it back, keeps the damaged database as `backups/library-damaged-<time>.db`, reopens the library and checks it again.
- Processing settings (E17-S03, MFC-132): Settings, Processing has the number of file reading, thumbnail and image, and AI analysis jobs that run at once (the thumbnail and image default fits the computer), what happens to unfinished work when a library opens (continue automatically, or wait until you start it), and "Ask before quitting while processing". A changed limit takes effect at once, without a restart: more queued work starts now, and a lower limit applies as running work finishes. "Reset this category" puts the limits back to the recommended ones. When a library opens with processing waiting for you, the status bar says "Processing paused" and the processing queue shows a Resume processing button.

- Remove items from the library (E02-S10, MFC-123, D024): "Remove from library" in the Item menu, the context menu and the details panel (also with several items selected), and with `Delete` in the browser, removes the selected items after one confirmation ("Don't ask again" turns it off; Settings, General, "Ask before removing items from the library" turns it back on). The files stay on disk. The items leave search, browsing and collections at once, keep their tags, descriptions, ratings and collections, and lose their AI results, embeddings and thumbnails (in the background for more than 200 items). Rescans leave them out, also when their file is moved or renamed. Library, "Excluded items…" lists the removed items: Restore imports them again (an item whose file is gone becomes Missing), and Forget deletes them with their edits, after a warning; a forgotten file that's still in an indexed folder comes back as a new item with the next scan.

- Library statistics (E02-S05, MFC-120): View, Library information opens a small window next to the main window with the item counts (images, animated images, videos), the status counts (indexed, pending, with errors, missing; removed items never count) and the disk use (media files, database, thumbnails, backups, total, measured in the background and shown as "Calculating…" until it is in). The numbers follow imports and analysis live, at most once a second. The status bar's right end shows "12,345 in library · 340 pending" (the pending part is hidden at zero); click it to open the same window. Counting 100,000 items takes about 43 ms.

- In-app notifications (E15-S01, MFC-129): short toasts at the bottom right, above the status bar, never modal, at most four at a time. Information and success toasts go away after 6 seconds (not while the pointer or the keyboard is on them); warnings and errors stay until you close them. Each finished import or analysis job raises one notification, however many items it had: "Imported N items" with Show imported items, "View failed items" when some or all items failed. Cancelled jobs stay quiet. Settings, General, "Show informational notifications" hides the information and success ones, never warnings or errors. Library, "Recently imported" selects that entry of the navigation panel.

- Import by selecting files (E03-S05, MFC-124): Library, "Import files…" (also on the toolbar, Ctrl+Shift+I) opens a multi-select picker filtered to media files. A picked file inside an indexed folder joins it; otherwise its folder is added as a "Selected files only" folder that tracks just the picked files: its rescans check only those files and it has no rules. Picked files are imported in the background, and a message says how many are being imported, already in the library, not supported or unreadable. A file you removed from the library is restored when you pick it. In Library, "Manage folders…", a selected-files-only folder shows "Index whole folder", which, after a question, imports everything in it and keeps the items already there with their metadata; adding that folder with Add folder does the same, and adding a folder inside it moves its items under that folder to the new one. The library database moves to schema 15 (existing folders stay full folders).

## M3 — 2026-11-20

### Added

- Bulk metadata editing and tagging (E07-S03): selecting several items shows the metadata editor for all of them in the details panel, with what they share, "Multiple values" where they differ and each tag with how many items have it. Typing sets a field on every item, Clear empties it, and tags are added, removed or rejected on the items that have them; fields you don't touch stay as they are. Saving more than 20 items asks first, and more than 500 show progress with a Stop button that keeps what was written. Undo (in the bar after saving, Edit, Undo, or `Ctrl+Z` while several items are selected) puts the last bulk edit back for the session. Selecting several items while the single-item editor has unsaved changes now holds that editor like selecting another item does.
- Provenance display and AI-value actions (E07-S11): each field in the metadata editor shows a mark for its stored value (AI, Edited, Accepted) with the model and date in its tooltip, and a New suggestion mark where the AI now has a different value than yours. A field has Confirm AI value and Use the AI or file value, and a suggestion has Accept suggestion and Dismiss (tags too, with Enter and Shift+Enter on a chip); all are staged until Save and Undo takes them back. A field the describer can't produce says "Not available with the current model". The staged-change mark now reads "Unsaved" so it isn't mistaken for the Edited mark.
- Unsaved-changes guard and concurrent changes (E07-S12): selecting another item (including previous and next in the preview), collapsing or hiding the details panel, opening another library and closing the app ask Save, Discard or Stay while the metadata editor has staged changes. Enter saves, Esc stays, and a save that fails keeps you where you are. Other editors can register with the same guard (`UnsavedChangesGuard`). When the shown item changes in the background (for example a re-analysis finishes), fields you didn't edit refresh and your staged values are kept, with a notice naming the fields that changed under you. If a search or filter removes the edited item from the results, the panel keeps it until you save or cancel.
- Metadata editor (E07-S02): the details panel's Overview tab edits the shown item's title, description, summary, notes, AI analysis fields and tags, with Save and Cancel (D019). Changed fields are marked, a field can go back to its AI or file value, and the service's validation errors show next to the field. Tags are chips with their source (yours, AI, from the file) that can be added, removed (your own) or rejected (any), with autocomplete from the library's tags, most used first, and full keyboard use. Edit metadata (`F2`, or `E` in the browser and viewer) moves the keyboard to the editor; `Ctrl+S` and `Esc` save and cancel.
- In-process describer (E06-S04-T01): Florence-2 base (MIT) describes items without a server, on the CPU: a detailed caption as the description, a short caption as the summary, and the detected objects as objects and tags (5.6 s per image on the reference laptop). Florence-2 large can be chosen in the analysis profile. A configured vision-language model server stays the default describer, and items wait for it while it is down instead of getting Florence-2's shorter description.

- Whole-clip descriptions (E06-S04-T07): a video or animation is described from up to 6 keyframes (512 px) in one request to a vision-language model, instead of from its middle keyframe; a describer that takes one picture describes up to 4 keyframes and their lists and tags are merged by frequency.
- Vision-language model describer prompt describe-2 (E06-S04-T02): the default prompt is the describer spike's winner (prompt C, scored with qwen3-vl-4b in LM Studio). A clip's frames are introduced by the prompt itself, and the caller's context is kept. Items described with describe-1 show as outdated.
- Versioned describer prompts (E06-S04-T04): the vision-language model describer's prompt is an embedded template with a version (`describe-1`); the analysis profile's prompt version picks one, the run stores the version used, and choosing another template or shipping a newer default marks described items as outdated. A test pins each template's text to its version.
- English and Russian tags (E06-S04-T09, D035, D047, D348): a curated dictionary of 2,141 English tags with one Russian base form each gives AI tags, tags the user types and file keywords their other-language form, marked as derived, and the keyword index holds both, so "кошки" finds an item tagged "cat" and "cat" finds one tagged "Кошки". Russian input is matched by Snowball stem; forms whose stems collide are matched only as written. Accepting a tag keeps its form. The tag filter and its autocompletion match a tag by either form through an indexed upper-case key (`other_form_key`), so "пляж" and "beach" give the same items and counts. Library schema 14 stores the form and its key on each tag assignment, and upgrading fills them in for existing tags without a rebuild. With describe-2 the vision-language model writes the Russian form of each tag and of the title itself: a tag keeps the model's form (not marked as derived) unless it is blank or equal to the tag, which falls back to the dictionary; the Russian title is stored with the title and indexed for keyword search, and accepting the AI title keeps it.
- Russian keyword search across word forms (E06-S04-T10, D349): the keyword index stores the Snowball stem of every Russian word in an item's metadata (library schema 14; upgrading copies the index once, without a rebuild), and a Russian query word also matches its stem, so "собаки" finds "собакой".
- AI tag normalisation (E06-S04-T05): the describer's tags lose surrounding punctuation and extra white space, a capital that is only the first letter is lowered, English tags become singular (Humanizer, with a list of words kept as written), synonyms are mapped ("automobile" → "car") and generic tags ("photo", "image", "фото") are dropped, so "Dogs", "dog" and " Dog " are one tag. `settings.json` `tags.stopwords` and `tags.synonyms` replace the built-in lists.

- Keyframe OCR merging: near-duplicate lines from different keyframes of a video or animation (same digits, letters within 20% edit distance, at least eight letters) are stored once, as the most frequent variant.

Files are found, fingerprinted, read for metadata and thumbnailed in parallel, appear as Pending analysis as they're registered, and are hashed in full afterwards at low priority so exact duplicates are grouped; a failed file is marked Error with its stage and can be retried, damaged files only once they change; imports resume after a restart, can be cancelled, and never create duplicate items (library schema version 5, E03-S07).
- Navigation panel: Library (All media, Recently imported) and Folders sections with live counts; the folders tree shows subfolders from the indexed items, marks Offline folders, and scopes the media browser to the selected folder or subfolder; Excluded items are no longer shown; sections collapse and stay collapsed; the collapsed panel is an icon rail; folders dropped on the panel are added through the folders dialog (E13-S02).
